# 拟人化小说生产方案

这份方案描述真人作者/编辑通常如何把一个小说想法变成可读章节，并把流程拆成系统可执行的生产步骤。

## 真人写作通常怎么做

真人作者不会直接“生成一章”。更常见的顺序是：

1. 先确认故事承诺  
   这本书到底给读者什么持续期待：爽点、情绪、题材钩子、主角魅力、升级或破局方式。

2. 逐项确认核心设定  
   主角是谁，想要什么，缺什么；世界如何运转；能力能做什么、代价是什么；长期压力从哪里来；什么套路不能写。

3. 把一卷拆成剧情段  
   明确这一段从哪里开始、要把主角推到哪里、高潮是什么、转折是什么。

4. 写每章前先做章内设计  
   作者会先想：本章开场在哪里，主角此刻想解决什么，阻碍是什么，读者能看到什么新信息，章末为什么要追读。

5. 把章节拆成连续小单元  
   通常不是一口气写完，而是按 300-700 字左右推进：一个小目标、一个阻碍、一个反应、一个信息增量、一个局面变化。

6. 写完后从读者体验回看  
   检查是否开场能读、主角是否主动、因果是否连贯、设定是否自然、代价是否可见、章末是否有期待。

7. 修改时先理解意见，再改正文  
   好作者不会机械替换词句，而是判断意见背后的真实问题：节奏、动机、爽点、场景、文风、设定兑现或读者期待，然后让正文产生可见变化。

## 系统生产拆解

### A. 骨架逐项确认

进入正文生产前，以下项目需要人工确认：

- 一句话核心设定
- 读者承诺
- 世界规则 / 能力曲线
- 主角动力 / 成长弧
- 长期冲突 / 主线
- 禁忌规则
- 文风指南
- 第一卷摘要
- 剧情段目标
- 剧情段高潮
- 剧情段转折

任意项目被修改后，原确认失效，需要重新确认。

### B. 章节生产标准

每章必须满足：

- 正文 3000-4500 中文字符
- 开篇 300-700 字内进入具体处境，可以用人物欲望、关系张力、异常细节、利益交换、行动后果或悬念形成牵引，不强制同款危机开场
- 主角行动链完整：目标 -> 阻碍 -> 主动选择 -> 可见代价 -> 结果变化
- 按约 500 字小单元推进
- 后一单元承接前一单元后果，不跳成剧情梗概
- 每 2 个单元至少有一次人物对话或互动
- 新设定由事件、对话、异常或后果触发
- 主角获得一次阶段性主动权，同时付出代价
- 章末钩子必须由本章行动引发

### C. 小单元生产法

每个小单元都要回答：

- 本单元主角的小目标是什么？
- 当前阻碍是什么？
- 主角做了什么可见动作？
- 人物有什么反应或互动？
- 读者获得了什么新信息？
- 单元末局面发生了什么微变化？

系统正文里不显示“单元一/单元二”，但生成和续写都按这个逻辑推进。

### D. 修改意见处理法

人工意见必须作为原始意见保留，并被转译为：

- 要删除、保留或替换的场景
- 主角需要改变的选择或行动
- 读者体验要发生的变化
- 设定或能力需要如何可见兑现
- 章末期待需要如何变化
- 验收时能逐条看到的正文结果

### E. 审稿门禁

审核不只判断有没有冲突和钩子，还要判断：

- 是否像完整章节，而不是短场景
- 是否按小单元自然推进
- 是否有人物反应和互动
- 是否有连续因果
- 是否真正回应人工意见
- 是否值得读者继续读

## 当前实现状态

2026-06-06 已落地多圈生产闭环：

- `app/services/chapter_units.py`：把章节切成 300-700 字小单元，逐单元检查目标、动作、阻碍、后果、信息增量、反应、承接和表达准确性。
- `app/services/quality.py`：质检报告新增 `chapter_unit_flow` 维度和 `chapter_unit_report` 明细；当前作为诊断和修复依据，不作为硬门禁一票否决。
- `app/services/chapter_revision.py`：生成修订 brief 时会读取小单元报告，把失败单元转成可执行的修复合同。
- `app/services/chapter_unit_plans.py`：生成前保存 6-8 个结构化小单元计划，并把计划注入导演单。
- `app/services/production_llm.py`：草稿/修订生成后会自动做小单元验收；低于阈值时优先只返修失败单元，并按失败类型选择承接、反应、动作、阻碍、后果、信息增量等局部返修策略；局部返修不成立时再回退整章返修；只有单元流不倒退且长度不塌掉才接受新稿。
- `app/services/production_run_review.py`：每次草稿/修订完成后沉淀生产复盘记录，记录计划兑现、实际单元数、返修方式、弱单元、问题和下一步建议；同时从最近复盘中汇总常见失败模式，形成生产模式记忆。
- `app/services/production_packet.py`：下一章生产会自动读取生产模式记忆，把“承接断裂、人物反应弱、实际单元数偏少”等最近常见问题注入导演单和小单元计划验收项。
- `app/dashboard_assets.py`：写作台诊断摘要显示计划-正文对账、生产复盘和模式记忆；质检详情显示拟人化小单元分数、单元列表和修复合同；前台主操作不增加复杂按钮。
- `scripts/chapter_unit_regression.py`：覆盖小单元诊断、失败单元局部返修和整章回退返修，防止后续迭代退回一次性整章生成。
- `scripts/chapter_unit_plan_regression.py`：覆盖单元计划持久化、提示块生成和计划-正文对账。
- `scripts/production_run_review_regression.py`：覆盖生产复盘摘要、返修模式和弱单元建议。

下一轮优先方向：

- 将复盘记录与市场信号、读者反馈关联，形成“哪类单元问题影响追读”的长期画像。
- 让模式记忆按题材、作品阶段、章节位置分层，避免早期章节的问题过度影响后续卷段。
- 在不增加前台按钮的前提下，把“系统记住了什么”合并进主按钮旁的一句话提示。
