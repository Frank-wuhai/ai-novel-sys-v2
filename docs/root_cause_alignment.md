# 生产偏差根因分析

当作者已经把方向说清楚，但系统仍写偏时，不能继续只靠追加 prompt 或手工改库。更根本的问题通常是：作者意图没有变成可执行、可检查、可继承的生产契约。

## 当前问题的本质

以《我的武侠游戏存档，正在现实同步加载》为例，作者真正要的是：

- 《大江湖》像真实武侠世界，玩家进入近似穿越。
- 江湖人物有门派、利益、恩怨、恐惧、欲望和生活，不是任务 NPC。
- 主角提升遵循这个世界的规则：修炼、拜师、交易、冒险、结交或得罪具体的人。
- 套路触发器是陈默的个人金手指，不是网游评分系统。
- 不能写成打怪升级、刷经验、刷副本、机械任务链。

如果这些只存在于一次人工对话里，而没有同步进入 StoryFoundation、StoryBible、WorldRule、PowerSystem、ChapterBrief、导演单和质检标准，模型就会自动回到最常见的“游戏系统文”路径。

## 四类根因

1. 意图没有结构化

   “真实武侠世界”必须拆成可执行规则：人物如何反应、成长如何发生、能力如何触发、哪些写法禁止。否则模型只会把它理解成氛围词。

2. 上下文源头不同步

   系统同时读取故事地基、圣经、Canon、作者口味、章节 brief、旧稿、质检报告和修订建议。只要其中某一层仍保留旧方向，后续生产就会被拉偏。

3. 质检与作者意图脱节

   通用质检能查字数、动作链、钩子，但不能天然知道“这里不能写成机械游戏”。题材核心要求必须进入质检和审稿，否则一章可能技术上过关，方向上失败。

4. 修改意见没有被验收化

   人工意见不能只作为一句话塞给模型。它需要转成可验收结果：删掉什么、保留什么、替换什么、读者体验要发生什么变化、哪些正文证据能证明改对了。

5. 系统偏差和模型偏差混在一起

   系统偏差来自生产链路本身：旧 brief、旧质检、旧稿、长上下文或互相冲突的规则把模型带偏。模型偏差来自模型的默认补全习惯：一看到“游戏”，就自动补成任务大厅、经验值、刷副本、NPC 发任务和数值奖励。

   这两类问题必须分开诊断。系统偏差要清理上下文；模型偏差要加题材护栏和质检硬门禁。

## 以后怎么判断问题出在哪里

先跑方向对齐审计：

```bash
python -m app.cli story-alignment-audit --book-id 2 --chapter-limit 5
```

再针对具体章节跑偏差审计：

```bash
python -m app.cli chapter-bias-audit --book-id 2 --chapter-number 3
```

看四件事：

- `source`：故事地基、圣经、世界规则、能力体系、作者口味是否同向。
- `brief_positive`：每章 brief 是否显式承接核心作者意图。
- `brief_stale`：最新 brief 是否仍夹带旧质检报告、旧修订合同、旧失败建议。
- `content_negative`：最新正文是否仍出现反方向写法。
- `system_bias_hits`：生产上下文是否夹带旧质检、旧修订合同或旧稿污染。
- `model_bias_hits`：正文是否滑回模型默认套路，如任务大厅、经验值、刷副本、系统任务。

## 判断规则

- 地基没对齐：先改 StoryFoundation / StoryBible，不要生产正文。
- 地基对齐但 brief 没对齐：先重建章节 brief，不要重写正文。
- brief 对齐但正文没兑现：问题在正文 prompt、模型能力、旧稿参考权重或采样参数。
- 正文已经偏得很重：用 fresh 重写，不要局部修补。
- 只有词句或小段落偏：用 `local_patch` 最小补丁，只改命中问题。
- 有可用结构但局部桥段不成立：用 `targeted` 定点修订，并给出可验收修改点。
- `model_bias_hits` 有命中：不要人工审批通过，必须修订或 fresh 重写。
- `system_bias_hits` 有命中：先清上下文，不要继续烧正文 token。

## 已加入系统的治理机制

- 生产上下文裁剪：正文生产不再无差别吞入长骨架、旧质检、旧稿和历史建议，而是裁剪成当前章真正需要的市场证据、Canon、作者口味、前章承接和必要旧稿片段。
- 作者意图验收：质检会额外判断正文是否兑现了 brief、约束、Canon 和作者口味；如果方向没兑现，会标记为 `intent_underfulfilled`。
- 失败归因：前台会把问题归类为 `context`、`model_drift`、`intent_underfulfilled`、`quality` 或 `ready_or_manual_judgment`，并给出下一步动作。
- 修订路径拆分：`local_patch` 只修词句/短段落，`targeted` 保留可用结构后定点重写，`rewrite` 允许结构重做，`fresh` 按最新骨架重启且不参考旧稿。
- 偏差硬门禁：真实武侠世界这类方向一旦正文出现“送经验、刷副本、任务大厅、经验值”等模型默认套路，会阻断审批和继续通过。
- 确定性局部补丁：当 `local_patch` 只命中明确模型偏差词时，系统优先做最小文本替换并生成新版本，不再为了一个词调用模型整章重写。
- 复检幂等：已经通过或未通过的章节允许再次质检并更新报告，不因状态相同而报错。

## 后续开发原则

系统应该让作者做方向判断，而不是让作者充当数据库管理员。

因此后续每次生产前，系统应自动做一次轻量方向审计：

- 有 blocker 时不继续烧 token。
- 有旧 brief 污染时提醒先清理。
- 只有上下文同向时才进入正文生产。
- 正文生产后再比较“brief 说了什么”和“正文兑现了什么”。
