# 作者模式主流程

本文件描述 AI Novel System v2 的日常作者工作流。作者不需要理解后台队列、模型路由、数据库迁移或修订模式；系统默认只给出一个主动作。

## 1. 新建或选择作品

作者只需要提供书名、类型、平台和一句核心想法。

系统负责补齐或诊断：

- 故事承诺
- Story Bible
- 世界规则
- 主角动力
- 长期冲突
- 第一卷和剧情段骨架
- 初始章节 brief

主动作：`一键补齐并创建` 或 `进入写作台`

## 2. 作品设定

系统显示骨架是否可生产，而不是要求作者逐项操作后台表。

主动作：`诊断并修复`

修复只在作者确认后写入数据库。缺失市场证据、Canon、Story Bible、剧情段或章节 brief 时，系统生成修复草案。

## 3. 写作台

写作台是默认首页。它根据当前章节状态自动判断下一步：

- 创建 brief
- 排队生成草稿
- 执行队列任务
- 质检章节
- 生成修订 brief
- 执行修订
- 等待作者阅读
- 审批章节
- 准备发布

主动作：`继续写作`

失败时写作台必须显示卡点，例如缺少骨架、队列失败、质量未过、需要人工审批或发布配置缺失。

## 4. 自然语言修订

作者只输入真实感受，例如：

- 这段太像说明书。
- 章末钩子不够明确。
- 主角还是太被动。
- 整章没写出我要的感觉。
- 不要参考旧稿，按最新设定重新来。

系统自动判断处理强度：

- 局部补丁：只改句子、词语或短段落。
- 润色：保留结构，处理文风、对白、节奏和自然度。
- 定点修订：保留主结构，替换失败场景、行动链或章末钩子。
- 结构重写：旧稿只作 Canon 弱参考，按最新骨架重做本章。
- Fresh 重启：旧稿方向会污染后续，按最新骨架重新设计。

作者不需要选择这些内部模式。系统会把判定理由、保留内容、替换范围和升级规则写入修订合同。

## 5. 质量与审批

章节必须通过质量门禁后，才进入阅读和审批。

作者审批只处理两个问题：

- 能不能接受当前章作为正式版本？
- 如果不能，给出自然语言修改意见。

系统根据意见自动退回修订，不要求作者理解内部状态机。

## 6. 发布准备

发布只在章节已审批后进入。

主动作：`准备发布`

系统先创建 publish job，再执行 dry-run。真实平台发布必须显式确认，并且需要平台目标配置已经完成。

## 7. 高级诊断

以下内容默认折叠：

- 生成队列
- 失败任务
- LLM 请求与成本
- 数据库备份和恢复
- 发布目标配置
- 质量细分报告
- Story/Canon/Evidence 上下文
- 回归和系统诊断

这些面板用于排错，不参与日常写作主线。
